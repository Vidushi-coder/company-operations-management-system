## Overview

This document defines each entity in the system, its attributes, data types, and constraints. It also defines the relationships between entities. This file serves as the direct reference for creating the ER Diagram in the next phase.

The system contains **5 core entities:**

- Users
- Employees
- Projects
- Tasks
- Leave Requests

---

## Entities

### 1. Users Entity

**Description:** Represents a system account used for authentication and access control. Every person who logs into the system has a User entity.

**Primary Key:** `_id` (auto generated by MongoDB)

| Field       | Data Type | Constraint       | Description                              |
|-------------|-----------|------------------|------------------------------------------|
| _id         | ObjectId  | Required, Unique | Auto generated unique identifier         |
| name        | String    | Required         | Full name of the user                    |
| email       | String    | Required, Unique | Email address used for login             |
| password    | String    | Required         | Stored as a hashed value, never plain text |
| role        | String    | Required         | Access level: Admin / Manager / Employee |
| createdAt   | Date      | Required         | Timestamp of when the account was created |

---

### 2. Employees Entity

**Description:** Represents a person working at the organization. Stores personal and professional details. Every Employee is linked to exactly one User account.

**Primary Key:** `_id` (auto generated by MongoDB)  
**Foreign Key:** `userId` references the Users entity

| Field         | Data Type | Constraint       | Description                                        |
|---------------|-----------|------------------|----------------------------------------------------|
| _id           | ObjectId  | Required, Unique | Auto generated unique identifier                   |
| userId        | ObjectId  | Required, Unique | References the linked User account for this employee |
| name          | String    | Required         | Full name of the employee                          |
| email         | String    | Required, Unique | Contact email address                              |
| phone         | String    | Required         | Contact phone number                               |
| department    | String    | Required         | Department the employee belongs to                 |
| designation   | String    | Required         | Job title or role of the employee                  |
| dateOfJoining | Date      | Required         | Date on which the employee joined the organization |
| status        | String    | Required         | Current employment status: Active / Inactive       |

---

### 3. Projects Entity

**Description:** Represents a project created within the organization. A project can have multiple employees assigned to it as members and can contain multiple tasks.

**Primary Key:** `_id` (auto generated by MongoDB)  
**Foreign Key:** `createdBy` references the Users entity  
**Foreign Key:** `members` references multiple Employee entities

| Field       | Data Type        | Constraint | Description                                              |
|-------------|------------------|------------|----------------------------------------------------------|
| _id         | ObjectId         | Required, Unique | Auto generated unique identifier                   |
| title       | String           | Required   | Name of the project                                      |
| description | String           | Required   | Brief overview of what the project involves              |
| status      | String           | Required   | Current state: Not Started / Active / On Hold / Completed |
| startDate   | Date             | Required   | The date on which the project officially begins          |
| deadline    | Date             | Required   | The final date by which the project must be completed    |
| createdBy   | ObjectId         | Required   | References the userId of the Admin or Manager who created the project |
| members     | Array of ObjectId | Optional  | List of employee IDs assigned to this project            |

---

### 4. Tasks Entity

**Description:** Represents an individual unit of work created under a specific project and assigned to a specific employee. Every task must belong to a project.

**Primary Key:** `_id` (auto generated by MongoDB)  
**Foreign Key:** `projectId` references the Projects entity  
**Foreign Key:** `assignedTo` references the Employees entity  
**Foreign Key:** `createdBy` references the Users entity

| Field       | Data Type | Constraint       | Description                                              |
|-------------|-----------|------------------|----------------------------------------------------------|
| _id         | ObjectId  | Required, Unique | Auto generated unique identifier                         |
| title       | String    | Required         | Name of the task                                         |
| description | String    | Required         | Details of what needs to be done for this task           |
| priority    | String    | Required         | Urgency level: High / Medium / Low                       |
| status      | String    | Required         | Current progress: To Do / In Progress / Done             |
| projectId   | ObjectId  | Required         | References the project this task belongs to              |
| assignedTo  | ObjectId  | Required         | References the employee responsible for completing this task |
| createdBy   | ObjectId  | Required         | References the userId of the Admin or Manager who created the task |
| dueDate     | Date      | Required         | The deadline for completing this specific task           |

---

### 5. Leave Requests Entity

**Description:** Represents a leave application submitted by an employee. Stores the leave details, current approval status, and information about who reviewed the request.

**Primary Key:** `_id` (auto generated by MongoDB)  
**Foreign Key:** `employeeId` references the Employees entity  
**Foreign Key:** `reviewedBy` references the Users entity

| Field       | Data Type | Constraint       | Description                                                        |
|-------------|-----------|------------------|--------------------------------------------------------------------|
| _id         | ObjectId  | Required, Unique | Auto generated unique identifier                                   |
| employeeId  | ObjectId  | Required         | References the employee who submitted this leave request           |
| leaveType   | String    | Required         | Category of leave: Sick Leave / Casual Leave / Annual Leave        |
| fromDate    | Date      | Required         | The starting date of the requested leave period                    |
| toDate      | Date      | Required         | The ending date of the requested leave period                      |
| reason      | String    | Required         | Explanation provided by the employee for requesting leave          |
| status      | String    | Required         | Current state of the request: Pending / Approved / Rejected        |
| reviewedBy  | ObjectId  | Optional         | References the userId of the Admin or Manager who reviewed the request |
| appliedAt   | Date      | Required         | Timestamp of when the leave request was submitted                  |

## Relationships Between Entities

### Relationship Summary Table

| Entity A       | Relationship | Entity B        | Description                                               |
|----------------|--------------|-----------------|-----------------------------------------------------------|
| Users          | One to One   | Employees       | One User account is linked to exactly one Employee record |
| Projects       | One to Many  | Tasks           | One Project can contain many Tasks                        |
| Employees      | One to Many  | Tasks           | One Employee can be assigned many Tasks                   |
| Projects       | Many to Many | Employees       | One Project can have many Employees, one Employee can be in many Projects |
| Employees      | One to Many  | Leave Requests  | One Employee can submit many Leave Requests               |
| Users          | One to Many  | Projects        | One User (Admin/Manager) can create many Projects         |
| Users          | One to Many  | Tasks           | One User (Admin/Manager) can create many Tasks            |
| Users          | One to Many  | Leave Requests  | One User (Admin/Manager) can review many Leave Requests   |

---

### Relationship Details

**Users → Employees (One to One)**  
Every Employee must have exactly one linked User account. This link is established through the `userId` field in the Employees entity. A User account can exist without an Employee record only in special cases such as a system Admin who is not listed as an employee.

**Projects → Tasks (One to Many)**  
A Project can contain many Tasks but each Task belongs to exactly one Project. This relationship is established through the `projectId` field in the Tasks entity. If a Project is deleted, all its Tasks must be handled accordingly.

**Projects → Employees (Many to Many)**  
A Project can have many Employees assigned to it and an Employee can be a member of many Projects at the same time. This relationship is stored through the `members` array in the Projects entity which holds a list of Employee IDs.

**Employees → Tasks (One to Many)**  
An Employee can be assigned many Tasks across different projects but each Task is assigned to exactly one Employee at a time. This relationship is established through the `assignedTo` field in the Tasks entity.

**Employees → Leave Requests (One to Many)**  
An Employee can submit many Leave Requests over time but each Leave Request belongs to exactly one Employee. This relationship is established through the `employeeId` field in the Leave Requests entity.
